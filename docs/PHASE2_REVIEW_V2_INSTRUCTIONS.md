# Independent human review — Stage 14B v2

Open [the review workbook](../data/phase2/review_v2/phase2_human_review.xlsx) in Excel or another XLSX editor and save a **new copy**. The original unreviewed [CSV files](../data/phase2/review_v2/) are also available, and the v1 originals remain unchanged in `data/phase2/review/`. This package is version `stage14b-v2`: 70 questions and 273 initial candidate pairs. It has no retrieval rankings and no human labels.

1. A real person independent of both question authorship and candidate selection reviews every row of **Questions**. Use `yes`, `no`, or `unknown` for `question_valid`, and record a consistent reviewer identity or pseudonym, `independent_of_author=yes`, and the actual UTC timestamp in ISO format such as `2026-10-19T12:00:00Z`. Put suggested corrections in `rewrite_or_notes`, not directly in the question cell. The seven source-conditioned replacement questions are proposals, not approved decisions.
2. In **Pairs**, inspect the question, candidate passage, and source URL (copy the URL to a browser if your spreadsheet does not make it clickable). Read the full source context and relevant preprocessor conditions. Enter `1` only if the passage directly answers the need, `0` only if checked and irrelevant, or `unknown` when uncertain. Fill the uncertainty field (`none` if none), source-specific evidence/reason, confidence, reviewer identity, independence, and actual UTC timestamp for every row. Do not assume a different CVE title means irrelevant or that an absent macro proves hardware absence.
3. Pay particular attention to `esp-08`, `esp-11`, `esp-13`, `cve-01`, `cve-07`, `cve-15`, `cve-18`, the seven revised development needs, and the Apache cross-references. Decide whether the corpus itself supplies an appropriate answer and whether questions are unambiguous. See the separate [AI-assisted evidence report](PHASE2_AI_PREREVIEW.md) for source links and conflicting evidence; it is not a human judgment.
4. Preserve IDs, question text, passages, URLs, revisions and source hashes. Suggest new candidates or rewrites in notes rather than editing those fields; a new version must be prepared and reviewed if the dataset changes. Return the completed workbook together with reviewer identity/provenance, declaration of independence, and any unresolved questions. If feasible, arrange a second independent reviewer on a documented subset, preserving both independent reviews and recording disagreement and adjudication.

Validation from the repository root after receipt:

```powershell
.venv\Scripts\python.exe scripts/validate_phase2_human_review.py --workbook PATH_TO_COMPLETED_COPY.xlsx --output outputs/phase2/stage14b/returned_review_validation.json
```

The validator also accepts `--questions` and `--pairs` for completed CSV copies. A nonzero exit indicates missing, ambiguous or invalid review, changed source data, or flagged overlap. It checks self-attested reviewer metadata and UTC format but cannot establish that a reviewer is human, independent, qualified or correct. Even a clean run is **not** authorization to tune or evaluate: the protocol's manual review, source-coverage, independent-annotation and later blinded-pooling gates must still be satisfied. If a reviewer rejects a question or marks a pair unknown, preserve that judgment; resolve it through an explicit versioned decision, never coerce it to a positive or negative.

The v2 CSVs and audits can be regenerated with `python scripts/prepare_phase2_14b.py`; it refuses to overwrite CSVs containing recorded human review. To rebuild the workbook, serialize those CSVs with `python scripts/export_phase2_review_workbook_input.py <temporary-input.json>`, then run `scripts/create_phase2_review_workbook.mjs <temporary-input.json> <new-output.xlsx>` with Node and the bundled `@oai/artifact-tool` dependency. Do not overwrite a returned review. Generated XLSX files can have different package metadata even when all cells match, so use the validator for content round-trips.
