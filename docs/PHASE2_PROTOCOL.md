# Phase 2 preregistered protocol

**Established 2026-10-19, before Phase 2 corpus construction or retrieval evaluation.** The machine-readable rules are in [phase2_protocol.yaml](../configs/phase2_protocol.yaml). This is a research protocol, not evidence that the proposed sample or review exists.

## Question and hypothesis

For new, independently reviewed technical information needs containing supported explicit identifiers, does an identifier-aware adjustment selected **only on Phase 2 development data** improve mean MRR@10 relative to unchanged RRF? The directional hypothesis is an improvement; the study must report a zero or negative difference honestly. A selected zero-weight method is an acceptable outcome. Phase 1 is historical/regression material only: its inspected test outcomes must not determine Phase 2 weights or query selection. The separately fixed (0.003, 0.003) contrast is illustrative and exploratory, not the automatically selected method or an independent confirmatory claim.

## Corpus and query plan

Target 150 source-attributed passages (90 CVE, 60 ESP32) and 70 new unique queries (24 dev, 46 test). Target 18 identifier and 6 natural queries in dev, 34 identifier and 12 natural in test. These are effort targets, not power guarantees. Include at least 30 identifier-query near-miss cases with evidence-backed confusing candidates, five cross-reference cases, and five query cases involving multi-identifier passages where actual source content permits. A case can serve more than one quota; report each denominator and shortage. Seek heterogeneous prose and code passages. Do not invent source texts, cross-references, difficulty, or review to meet a quota.

Use pinned official CVE and Espressif sources only where the applicable rights and attribution are verified for the exact material before copying; preserve notices and raw hashes. Do not infer documentation rights from a code license. Exclude uncertain rights and maintain a source-specific evidence record. Target counts and balance can be lower only with an explicit shortfall and provisional status. If source availability, rights or annotation effort prevents a credible benchmark, stop the paper-grade claim rather than fill missing cases synthetically.

Create information needs before viewing retrieval rankings, preferably question-first; record author and whether a query was source-conditioned. Never describe agent-created queries as independent human-authored. Generate new IDs and text and exclude all old pilot test questions. Group and split topics/entities before selection using seed 42; prefer disjoint CVE entities and disjoint ESP variants, and where that is not feasible document shared variants and ensure the particular information need is disjoint. Audit exact duplicates, token similarity, topics and source overlap; no automatic similarity check proves semantic independence. Freeze query text, groups, corpus hashes and rubric before development selection. Human review of a query and independent relevance judgments are separate facts.

## Labels and human gate

Before rankings are exposed, prepare source-evidence-backed candidate positives and confusing candidates with query, passage text and source, proposed label, reasons and blank reviewer fields. Positive means the passage directly answers the need; a cross-reference may be positive even when the title names a different CVE. Explicit negative means an independently judged non-answer; ambiguous and unjudged pairs remain unknown. Do not count missing judgments as negatives. Require a real independent human reviewer for every test positive and pooled likely top conflicting candidate; log reviewer identity or stable pseudonym, independence, date, confidence and evidence. Aim for a second independent reviewer on 20% of cases and report actual agreement only if done; adjudicate disagreement or leave unknown. Validate a reviewed positive per query before final metrics.

Freeze the rubric before pooling. On dev, pool top 10 from lexical, dense, RRF and the fixed illustrative full reranker, de-duplicate, remove method labels, and request blind judgments before selection. On test, first freeze the chosen configuration, then generate and freeze rankings without reading test judgments, pool and blind the same candidates including the selected method, and have candidates independently reviewed. Do not use test judgments to modify parameters. A complete review package is not itself human review. If human review is unavailable, stop at the review gate; later experiments may only proceed as explicitly exploratory if the user separately authorizes that scope, and never as paper-grade effectiveness evidence.

## Methods, selection and outcomes

Keep the Phase 1 pretrained MiniLM, word TF-IDF, RRF k=60, parser and reranker unchanged unless a separately documented compatibility defect is fixed before the new final test. Use the same full corpus for all systems and deterministic document-ID ties. Do not train a model or add an unsupported IEEE parser. On reviewed dev data only, evaluate match {0, .003, .006, .012} × conflict {0, .003, .006}; save every run and per-query outcomes. Select lexicographically: maximize identifier MRR@10, minimize the conservative WrongIdentifier@1 upper bound, maximize Recall@5, minimize the sum of weights, then match, then conflict. Stop if no eligible identifier dev queries or reviewed known positives exist. Freeze selected weights, data/config/model/code hashes and package versions before test ranking.

Primary endpoint is identifier-query MRR@10 versus RRF. Secondary endpoints are known-positive Recall@5, binary nDCG@10, bounded adjudicated WrongIdentifier@1, timing and exact score/rank invariance on parser-free natural queries. Report eligible denominators, unknown counts, per-query and per-family results, paired gains/losses/ties and all ablations. Wrong-ID bounds are observed wrong / eligible through (observed wrong + conflicting unjudged) / eligible. Paired query-level bootstrap uses 10,000 resamples, seed 42 and a percentile 95% interval; grouped-topic sensitivity may be reported if justified. Separate warm component timings and one-time indexing from end-to-end throughput; report hardware. If a final-test defect drives a method change, preserve the run as exploratory and create a genuinely new test for later confirmation.

## Stage gates and preservation

Stage 13 verifies or transparently documents Phase 1 reproduction and commits this protocol before new Phase 2 experiments. Stage 14 must document source rights, split, evidence and benchmark validation. Stage 15 must have actual independent human review and documented coverage before paper-grade final evaluation. Stages 16–19 require frozen dev selection, blinded held-out rankings and reviewed judgments. Keep `data/technical`, `configs/final.yaml`, existing Phase 1 outputs and manifests unchanged; put Phase 2 artifacts in separate paths. Record failures, source shortfalls and protocol deviations, and create checkpoints. A retrospective or exploratory analysis cannot be promoted to a held-out confirmatory result.
