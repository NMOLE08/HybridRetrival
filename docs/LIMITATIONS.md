# Limitations and threats to validity

- This is a 31-passage smoke-test pilot with 10 identifier test queries and 2 natural queries, not a representative paper-scale benchmark. It samples CVE descriptions and code headers rather than a broad technical-document population.
- The same agent created source-conditioned queries and relevance judgments before the runs; there has been no independent human review or inter-annotator agreement study. Most query/document pairs are unjudged, including 342 test pairs. This can distort known-positive recall, MRR and wrong-ID estimates; relevance evidence and explicit negatives are saved for audit.
- The development split has only five identifier queries and all grid settings tied. The selected method is a no-op. Nonzero variants were frozen before test labels were read but were chosen after the dev tie; they are exploratory. The observed results do not establish improved retrieval, an optimal weight, or a benefit of the penalty.
- The confidence interval has only ten paired observations and does not account for dataset creation or annotator uncertainty. A bootstrap interval touching zero is not evidence of a reliable advantage; this is not a statistical significance claim.
- The parser covers specific CVE and ESP32 forms only; it does not parse IEEE standard identifiers, arbitrary versions, typos, aliases or semantic references. An absent detected conflict is not a verified correct answer. Cross-references can be relevant even when a passage's title names another identifier.
- Model input truncation can omit content from long source passages. Sources are shared between development and test; query strings are disjoint, but semantic independence is not proven. Test data have been inspected for this analysis and must not be reused for future parameter selection.
- Timing uses one CPU environment, a tiny corpus, warmed per-component calls and a cached embedding run; one-time embedding build comes from an earlier uncached run. It is not an end-to-end service benchmark and will vary by hardware and load.
- A larger benchmark with independently authored queries, comprehensive independent judgments, adversarial near misses, broader identifier families, a new locked test set and external replication is needed before claiming general performance or paper-grade validation. SciFact, if completed, tests general retrieval and parser coverage rather than technical-identifier correctness.
