# Preregistered experiment protocol

Created before implementation and before benchmark comparisons on 2026-10-18. Primary comparison is proposed reranking versus RRF for identifier-sensitive held-out technical queries. Report Recall@5 and MRR@10 as separate outcomes, alongside wrong-identifier@1 and confidence intervals when meaningful; no significance claim follows solely from a point estimate. Natural queries are a control whose scores and ranking must be identical when no supported identifier is extracted.

Relevance means a passage directly addresses the requested entity and information need; merely mentioning the identifier is insufficient. A multi-entity passage can be relevant. Unknown documents are unjudged, not necessarily negative; recall is over known positives and incompleteness limits conclusions. WrongIdentifier@1 requires an eligible query with an explicitly requested supported ID and a top passage explicitly judged as a wrong-variant outcome, containing a contradictory supported same-family ID but not the requested ID. Report its denominator and annotation policy; absent text alone is not a wrong variant.

Use source-backed, license-reviewed passages and evidence for judgments. Prepare independent query topics, prevent near-duplicate cross-split questions, record counts and hashes, and freeze test before dev tuning. Dataset construction and all labeling precede retrieval comparisons. Avoid pretending an agent review is independent human assessment; if unavailable, label this a pilot.

RRF uses k=60 with full ranks for small corpora, 1-based ranks, doc_id tie breaks and identical corpus. Add match fraction times lambda_match, less an explicit same-family conflict indicator times lambda_conflict. Test the predeclared grid match {0, .003, .006, .012}, conflict {0, .003, .006} on development only. Choose by lexicographically maximizing identifier-query MRR@10, then minimizing wrong-identifier@1, then maximizing Recall@5, then minimizing match+conflict and match, with a no-op selected if it ties; record all grid outcomes. Bonus-only uses the selected match weight with conflict zero. No revisions based on test outcomes without marking the prior test exploratory and constructing a fresh held-out test set.

Use seed 42 and pinned immutable model revision, exact configuration and dependency snapshots. Record preprocessing/model load separately from warmed query embedding, retrieval, and reranking, median and p95 with repeat count, hardware and timing conditions. Save rankings, scores, per-query metrics, aggregate slices, and manifests. Report negative results, source rights, missing judgments, sample sizes and threats to validity.

## Clarification before development grid (Stage 08)
WrongIdentifier@1 is observed only when a contradictory top document has an explicit negative judgment. An unjudged contradictory top document is unknown; report the eligible-query denominator, observed wrong count and unknown count, plus lower and upper bounds. For the predeclared dev selection tie-break, minimize the conservative upper bound `(wrong + unknown) / eligible`; this refinement prevents treating missing judgments as correct and was recorded before the grid was run. If there are no eligible development identifier queries, selection is not valid and must stop. Group nDCG uses binary relevance. A zero-known-relevant query receives metric value zero but is a dataset-validation error in the intended benchmark.
